## 优先 1：修复用户截图中的删除线

现象：用户回答中多段正文被横线划过，尤其出现在年代和数值区间附近。截图还有原始 `[chk_...]` 标记和重复显示的证据缺口。

当前代码直接 `st.markdown(answer.text)`，证据 snippet、背景解释等也直接按 Markdown 渲染。已检查当前安装的 Streamlit 前端：GFM strikethrough 插件的 `singleTilde` 默认开启，单个 ASCII `~` 也可以配对触发删除线。因此科学文本的近似符号或多个区间中的 `~` 可能把两处之间的大段文字划掉。具体触发位置需对照本地原始回答复现，不能把删除线解释成文献否定了该段内容。

- [ ] 用自建样例复现：`年代 251~16 Ma，含量 0.9~1.9，比例 30~175。`，以及多个段落、单个近似符号、双波浪线、已有转义字符。检查实际页面是否出现 `<del>` 或删除线。
- [ ] 修复展示层的 Markdown 字面量处理，覆盖主回答、背景补充、证据片段、证据不足提示以及用户原始提问中可能受影响的文本。
- [ ] 原始证据和回答字段保持不变；只在显示副本转义科学符号，或以保留字面量的组件显示证据。不能全局删除 `~`，不能盲目把所有 `~` 换成区间横线或“约”，因为它可能表达不同含义。
- [ ] 允许提示词要求自然中文使用清楚的区间写法，但展示层必须有兜底，不能只靠 LLM 避免输出符号。不要用 CSS 隐藏删除线来掩盖 Markdown 解析错误。

可采用以下仅处理波浪线、可重复调用的显示层辅助函数；把它纳入你选择的渲染策略，不改入库文本、索引 hash 或保存的 Answer。

```python
import re


def escape_markdown_tildes(text: str) -> str:
    def literal_tilde(match: re.Match[str]) -> str:
        slashes = match.group(1)
        extra = "\\" if len(slashes) % 2 == 0 else ""
        return slashes + extra + "~"

    return re.sub(r"(\\*)~", literal_tilde, text)
```

例如主回答用 `st.markdown(escape_markdown_tildes(display_text))`；英文证据可直接用字面量组件，或使用同样的转义。已有代码块/LaTeX 需按实际渲染策略保护，不要为转义破坏公式。补充必要的 Markdown 兼容测试，确保列表、加粗和合法引用显示正常。

验收：数值、正负号、科学记数法和同位素表达未改变；截图中那种整段删除线消失；重复 rerun 不累加转义；引用片段保持可核查。真实浏览器核查，不能仅测字符串包含反斜杠就声称修好。
