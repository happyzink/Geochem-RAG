## 用户需要的操作

用户双击启动后，应用自动获取当前配置的对话 provider 的可用模型一次；打开“设置”，也能点击“一键获取模型/刷新模型”。用户从实际返回的列表选择模型，选择是否思考以及低、中、高档位，保存后下一次问答使用该配置，无需修改代码或手动填写模型 ID。

截图只用于参考供应商设置的交互，不表示本项目必须复制截图中的 Anthropic 协议地址或 API Key 表单。当前项目是 OpenAI 兼容 Chat Completions 适配，密钥继续只来自独立的 `DEEPSEEK_API_KEY` / `SILICONFLOW_API_KEY` 环境变量（可通过已有 `.env` 加载）。不引入新的密钥持久化方式。

对话默认 DeepSeek、嵌入默认 SiliconFlow，保留既有 provider 切换能力。先把这两个已支持 provider 做正确，不扩展成任意厂商管理平台。

## 本轮查阅的接口资料

以下是 2026-10-12 查阅的官方资料，实施时仍以实际 provider 和模型返回值及最新官方定义为准，模型目录不能写死。

- [DeepSeek 模型目录](https://api-docs.deepseek.com/api/list-models/)：`GET /models`，模型信息可包含名称、上下文限制、effort 支持集合等。兼容旧响应只给 id 的情况；元数据缺失不能猜填。
- [DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)：OpenAI 格式的思考开关为 `thinking.type`，原生 effort 为 `low/high/max`；文档中的 `medium` 会映射到 `high`，不能声称二者是不同真实档位。
- [SiliconFlow 对话接口](https://docs.siliconflow.cn/docs/api/chat-completions-post)：可按模型支持情况使用 `enable_thinking`、`thinking_budget`、`reasoning_effort`。其中部分模型只提供 `high/max`，兼容输入 `low/medium` 也会映射到 high；不能通用套用 DeepSeek 参数。

这里只查阅接口文档，没有调用用户的模型目录或对话 API；不宣称账号当前有哪些可调用模型。

## 实施 1：模型目录获取

主要文件：`src/geochem_rag/providers.py`、`scripts/list_models.py`、`app.py`；必要时新增一个小型模型目录/能力模块，不重建 provider 架构。

- [ ] 启动或首次初始化页面时，按当前对话 provider 自动拉取一次模型目录；主界面保持简洁，获取结果展示在设置面板。启动期间只获取目录，不发送私有证据、生成回答或建立向量索引。
- [ ] 提供“一键获取模型/刷新模型”，显示加载状态、成功数量与更新时间。点击知识库、调整 top-k、提交问题等普通 rerun 不重复拉取目录。
- [ ] DeepSeek 采用其模型目录接口；SiliconFlow 可沿用实际支持的 chat/embedding 分类参数。当前 `list_available_models` 的 `/models?sub_type=...` 是原 SiliconFlow 实现，不能不分 provider 地照搬给所有接口。
- [ ] 保留模型 ID 与显示名称，按类型过滤：对话选择器不列 embedding/reranker/image-only 模型；能力未知时明确标记未知，不凭名字猜思考或 JSON 支持。
- [ ] 目录缓存隔离到当前会话/provider/endpoint/凭据上下文，切换 provider 或账户不能沿用另一账户的列表。更新目录失败时保留最后成功列表和时间并标注过期，不静默清空用户选择。
- [ ] 鉴权失败、限流、超时、无效 JSON、空列表分别显示清楚的中文错误；采用有上限的超时/重试，不因目录接口暂时失败把整个应用切到离线模式或隐藏错误。
- [ ] 列表可见不等于账号有实际调用权限。已保存模型未在列表中时标“待验证/不可用”，不要默默换成另一模型；提供重新选择或使用自建短提示进行显式连接测试。测试不发送私有知识库片段。
- [ ] 保留 CLI 模型目录命令便于排查，但日常用户通过设置按钮操作，不要求用户运行命令。

## 实施 2：选择模型并真正生效

- [ ] 设置面板中显示当前对话 provider、可搜索模型下拉框、思考开关、强度选项与“保存/应用”按钮。可显示非敏感连接信息，API key 不回显。
- [ ] 控件使用独立 UI key 与持久配置 key，采用回调或表单提交；不能再次出现控件创建后写同名 Session State 的异常。面板隐藏后配置仍保留。
- [ ] 应用设置后重建当前会话的 chat client/answerer，保留检索器和对话历史；下一次主回答及通用补充调用都使用新模型。不能只改标签、漏掉已有 answerer 持有的旧 provider。
- [ ] 对话模型选择不触发嵌入模型变化、重新导入或重建索引；会话配置不写入全局 `os.environ`，不影响其他用户会话。
- [ ] 使用已经解析的 provider 配置创建新实例（例如现有不可变配置的 `dataclasses.replace`），密钥仍取对应环境变量；改模型不能混用另一 provider 的 key 或 URL。
- [ ] 用户选择的 provider、模型 ID 和思考偏好可存入 Git 忽略的本地非敏感设置文件，重启后恢复；文件不包含 API key、私有问题、证据或调用记录。当前会话用户选择优先，其次已保存偏好，环境中的模型名作为初始化默认值；密钥始终来自环境变量。
- [ ] 在每条回答元数据中记录实际返回模型、provider、请求的应用档位和真正发送的 API 控制参数。历史回答保留当时信息，不能因切换模型而改写历史标签。
- [ ] 当前主链路结构化回答和引用校验继续有效。目录中不适用于现有结构化问答的模型需明确限制或完成适配，不能把未解析文本直接展示为成功回答。

## 实施 3：思考开关和低、中、高

要求是用户能控制 API 模型真实行为，不是通过提示词写“多想一点”或调整 temperature 来伪装。

### 能力与映射规则

模型能力优先由目录中的明确元数据确定，缺失时用经官方资料/测试确认的 provider+model 能力规则；未知能力不能默认为全部支持。保留原始 effort 值，不跨协议猜测。

| 模型实际支持 | 用户界面与请求行为 |
| --- | --- |
| `low/medium/high` | 低→low，中→medium，高→high |
| `low/high/max` | 可提供应用预设“低/中/高”，分别映射 low/high/max；面板明示“应用档位”及实际 API 值，不能向 API 发一个假定独立的 medium |
| 仅 `high/max` | 只允许对应的两个有效强度；低档禁用并解释本模型不提供该档，不用重复映射伪装成三个不同效果 |
| 仅思考开关 | 允许开启/关闭；强度控件禁用并说明不能分级 |
| 仅支持思考预算且定义明确 | 低/中/高可映射不同合规 thinking_budget，标注“预算预设”和具体预算；范围按模型定义校验，不能拿回答 max_tokens 冒充思考预算 |
| 固定思考模型，不能关闭 | 标记思考固定开启，关闭控件禁用，不发送无效开关 |
| 不支持或未知 | 相应控件禁用并给短说明，不发未验证参数 |

以上映射是本项目交互设计，不宣称不同 provider 的同名档位算力、质量或价格相同。默认采用已保存的有效偏好；首次选择能力已知的模型可默认关闭（若可关闭），用户开启后默认中档；固定思考/未知模型按真实能力处理。

### Provider 请求适配

- [ ] DeepSeek 思考开关按当前模型定义发送 `thinking={"type":"enabled"}` 或 `disabled`；只有支持的 effort 才传 `reasoning_effort`。当前 urllib 直接提交 JSON，字段应在实际请求 body 顶层；SDK 示例的 `extra_body` 不能原样嵌成 HTTP JSON 的额外层。
- [ ] SiliconFlow 使用其模型支持的 `enable_thinking`、`thinking_budget` 或 `reasoning_effort`，不要把 DeepSeek 的 thinking 对象不加判断地传过去。
- [ ] 不支持的 temperature/其他采样参数应按 provider 能力处理，不以忽略参数宣称设置生效。思考模式下的超时与输出预算需合理设置并明确错误，不能无限等待或自动重复昂贵调用。
- [ ] `reasoning_content` 与最终 `content` 分开处理，最终结构化 answer 仍从有效 content 解析；思考字段不当作引用证据，也不能因只有思考字段就返回正常成功回答。
- [ ] 所有正常回答、零证据补充及必要的辅助调用要明确使用哪一模型和思考策略；默认主回答与补充沿用用户选择，辅助查询转换如使用独立轻量策略必须明确记录，不静默串用。
- [ ] API 拒绝参数时回报不兼容并让用户重新选择，不偷偷忽略档位或降级模型。切换模型后重新验证旧档位是否适用，不携带上一模型的无效参数。

## 嵌入模型的范围

对话和嵌入选择始终分开。若界面也开放嵌入模型选择，放在高级设置、从 SiliconFlow embedding 目录获取；保存变化前显示“需要重新建立该模型的独立索引”，显式执行准备步骤后才可切换。绝不能把新模型的 query 向量放进旧空间检索；不自动删除现有可用索引。嵌入模型不显示思考选项。

## 协议与截图说明

当前 `providers.py` 调用 `/chat/completions`；截图中的 `/anthropic` 是另一种协议入口。不能复制该地址然后仍拼接 `/chat/completions`。本轮保留现有 OpenAI 兼容协议，对 base URL 做一致校验；若以后支持 Anthropic，需要单独适配和测试，不作为这轮必做内容。

## 验收与交付

新增相关测试可用 `tests/test_model_settings.py`、`tests/test_model_catalog.py`；扩展已有 `tests/test_providers.py` 和实际界面测试。

1. 首次启动自动获取一次，普通 rerun 不额外请求；一键刷新能请求新列表；目录失败可见并保留上次有效选择。
2. 不同 provider 使用正确 endpoint/key；chat 与 embedding 模型不混列；未知能力不猜测。
3. 选择两个不同对话模型，捕获下一次请求 body 的 model，验证主回答与补充实际更新；检索缓存、历史和私有库不受影响。
4. 支持三档的模型分别捕获三个真实不同且合法的控制值，关闭思考时参数正确。两档/仅开关/固定思考/未知能力的模型不能假装有三档。
5. 应用预设与 API 档位的映射可见；provider 忽略或合并的档位不能显示成独立生效。
6. 打开/关闭设置、切换知识库及重启后偏好保留；无 Session State 异常，无全局会话串扰，设置操作不触发 RAG 回答或索引重建。
7. 保存的偏好、日志和公开文件不含密钥/私有文本；显式连接测试使用自建短提示。
8. 在真实浏览器里完成“刷新模型→选择→设置思考→应用→中文问答”，核对实际返回模型与调用参数；不只凭控件截图称通过。
