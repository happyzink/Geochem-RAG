## 2. 为什么 PDF 有作者而引用匹配不上

### 已证实的数据流断点

```text
PDF 页面里的作者文字
    ↓ 抽取可成功
粗略作者识别（页眉/姓名分组仍会误判）
    ↓ 写入 candidate_authors
清单正式 authors=[]、year=None
    ↓ 导入器只读正式 authors/year，不读候选字段
Source.authors / Source.year
    ↓ Answerer 从 Source 取值，不从检索正文临时识别作者
作者—年份标签 / 待核实回退
```

1. **正文抽取成功不等于作者字段已识别。** 本地样本首页的真实作者可在抽取文本中找到，但 `/Author` 是平台标识；库里仍存该平台。新猜测函数对同页返回了 `Vol.`、`No.`，把卷期页眉误当作者。具体私有样本映射在本地复核结果中。
2. **单作者和姓名分组仍有缺陷。** 合成页“标题→张三→摘要”在平台元数据存在时返回空；合成英文作者行 `Alice Smith, Bob Jones` 被拆成四个作者。平台被过滤后没有正确回到完整署名行的解析流程。
3. **新版清单无条件置空正式作者/年份。** `scripts/inventory_local_pdfs.py` 的 manifest 构造把 `authors` 固定为 `[]`、`year` 固定为 `None`；候选值只放 `candidate_*`。保留不确定性是必要的，但确认/修正后回写正式字段的流程没有完成，而且重新 inventory 可能覆盖先前确认值。
4. **旧数据没有迁移。** 本轮重新读取活动库，仍有 18 个来源为 `["CNKI"]`、17 个没有作者、37 个没有年份。修改识别代码不会自动修改既有 `sources.jsonl`。
5. **新增上传未接书目识别。** `_render_pdf_upload()` 调用 `ingest_pdf(pdf_path, visibility="private", max_chars=...)`，没有传作者、年份和核实标题；`ingest_pdf()` 自身只是使用传入参数创建 Source，不会抽取书目信息。即使上传后续报错被修复，这条路径仍默认写空作者和年份。

## 3. P1：输入框切换模型/思考会调用被覆盖的同名函数

**位置：** `src/geochem_rag/app.py:217` 和 `:842`。

同一模块先定义 `_apply_settings(settings)`，后又定义 `_apply_settings()`；后者覆盖前者。新输入区按 `_apply_settings(new_settings)` 调用，实际产生：

```text
TypeError: _apply_settings() takes 0 positional arguments but 1 was given
```

复核通过加载当前源码中两个函数定义、按新输入区的调用方式执行确认，未调用在线 API。

- [ ] 分离界面回调与配置应用服务的名字/签名；所有入口共用校验、持久化和重建逻辑。
- [ ] 从真实控件切换到另一个模型及另一个档位验收，确认无 TypeError 且下一次请求参数变化，不能只验证下拉菜单能展开。

## 4. P1：新上传 PDF 在质量筛选处报错

**位置：** `src/geochem_rag/app.py:410`、`:424`。

`PageRecord.quality` 实际是字符串，上传函数却访问 `p.quality.value`。使用自建空白 PDF，执行当前 `_render_pdf_upload()` 的原样函数体，仅替换 UI 与隔离存储，已复现：

```text
AttributeError: 'str' object has no attribute 'value'
```

这发生在切块预览/入库之前，因此“看到了上传控件”不能证明上传闭环通过。

- [ ] 统一质量字段类型；测试有效文本 PDF、空白页、扫描/损坏页，全部走真实上传处理入口。
- [ ] 文件名目前只替换空格，需取合法 basename、拒绝路径穿越、验证文件内容；不能信任上传文件名。

## 5. P1：引用集合仍只检查了一个方向
